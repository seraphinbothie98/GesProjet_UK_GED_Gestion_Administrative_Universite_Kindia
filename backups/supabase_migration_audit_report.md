## 2. Anomalies trouvées

| Ligne | Table | Colonne | Problème | Correction | Risque |
|:---:|:---|:---|:---|:---|:---:|
| 127 | `archive_custom_categories` | `is_default_for_types_json` | `BOOLEAN DEFAULT '[]'` : type booléen incompatible avec une valeur par défaut de tableau JSON (Erreur PostgreSQL `22P02`) | Remplacé par `TEXT DEFAULT '[]'` conformément à la colonne SQLite source qui stocke des listes JSON | **ÉLEVÉ** (Corrigé) |
| 787 | `institution_settings` | `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY DEFAULT 1` : conflit de syntaxe PostgreSQL interdisant l'usage simultané d'une clause IDENTITY et d'un DEFAULT explicite (Erreur PostgreSQL `42601`) | Remplacé par `"id" BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,` sans clause DEFAULT redondante | **ÉLEVÉ** (Corrigé) |
## 3. Types corrigés

- **`archive_custom_categories.is_default_for_types_json`** : Typage erroné en `BOOLEAN` corrigé en `TEXT` (contenant du JSON avec défaut `'[]'`), aligné sur `associated_types_json`.
- **Intégrité de `users_temp`** : Conservation stricte des timestamps `TIMESTAMPTZ` (`last_login`, `created_at`, `updated_at`) et préservation des identifiants et valeurs `NULL`.
- **Types numériques et IDs** : Utilisation de `BIGINT GENERATED BY DEFAULT AS IDENTITY` pour toutes les clés primaires entières.
- **Dates et Horodatages** : Tous les horodatages convertis en `TIMESTAMPTZ` avec `NOW()` par défaut.

---

## 4. DEFAULT corrigés

- `archive_custom_categories` : `"is_default_for_types_json" TEXT DEFAULT '[]'`
- Audit de l'ensemble des 64 tables : Tous les booléens utilisent `DEFAULT TRUE` ou `DEFAULT FALSE`, tous les horodatages utilisent `DEFAULT NOW()`.

---

## 5. Contraintes corrigées

- **PRIMARY KEY** : 100% des tables ont une clé primaire définie (`id` en BIGINT ou `code`/`key` en TEXT).
- **FOREIGN KEY** : 100% des contraintes d'intégrité référentielle sont conservées avec réplication différée durant l'import (`SET session_replication_role = 'replica';`).
- **UNIQUE & NOT NULL** : Respect strict du schéma SQLite source (emails, matricules, codes uniques).

---

## 6. Index corrigés

- **97 index PostgreSQL** déclarés avec `CREATE INDEX IF NOT EXISTS` / `CREATE UNIQUE INDEX IF NOT EXISTS` pour assurer une recherche ultra-rapide sur les clés étrangères, statuts et dates.
